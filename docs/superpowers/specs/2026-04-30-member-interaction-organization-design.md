# 成员交互 + 宗门组织架构 — 设计文档

## 背景

当前成员页面只有静态展示（列表+详情弹窗），无交互功能。宗门页面只有基本信息展示，无组织架构管理。

## 设计目标

1. 成员详情弹窗增加"互动"功能，支持4种交互类型
2. 宗门页面增加"组织架构"板块，支持职位管理和人员安排

---

## 一、成员交互功能

### 1.1 UI 设计

**入口**：成员详情弹窗底部（装备板块下方），添加"互动"按钮。

```
┌─────────────────────────────────┐
│ 成员详情弹窗                      │
│ ...                              │
│ 装备板块                          │
├─────────────────────────────────┤
│ [       互  动       ]          │
│ [关闭]                          │
└─────────────────────────────────┘
```

**互动选择弹窗**：点击"互动"后弹出

```
┌─────────────────────────────────┐
│ 张三 — 互动                      │
├─────────────────────────────────┤
│ 每次互动消耗 1 点体力            │
│                                  │
│ [夸奖勉励 — 提升忠诚度与心情]     │
│ [批评责备 — 可能降低心情]         │
│ [邀请双修 — 修为相关互动]         │
│ [其他 — 自定义互动内容]           │
├─────────────────────────────────┤
│ [取消]                          │
└─────────────────────────────────┘
```

**"其他"输入弹窗**：选择"其他"后弹出

```
┌─────────────────────────────────┐
│ 自定义互动                       │
├─────────────────────────────────┤
│ <输入框：例如"赠送灵石"...>      │
├─────────────────────────────────┤
│ [确认] [取消]                    │
└─────────────────────────────────┘
```

### 1.2 交互流程

```
点击详情弹窗"互动"按钮
  → showMemberActions(memberName)
    → 弹窗选择互动类型
      → 选择"夸奖/批评/双修"
        → 弹窗关闭 → executeMemberAction(memberName, actionType)
          → addActionLog(actionType, memberName, content, 1)
            → alert("已记录，提交后推演")
      → 选择"其他"
        → 弹窗输入自定义内容
          → 确认 → executeMemberAction(memberName, '其他', customContent)
            → addActionLog('其他', memberName, content, 1)
```

### 1.3 操作类型与效果参考

| 操作 | 提示词中的描述 |
|------|---------------|
| 夸奖勉励 | 掌门对{成员}进行了夸奖勉励 |
| 批评责备 | 掌门对{成员}进行了批评责备 |
| 邀请双修 | 掌门邀请{成员}一同双修 |
| 其他 | 掌门对{成员}进行了{自定义内容} |

### 1.4 提示词构建（submitActions）

成员互动 actionLog 的 category 为：'夸奖勉励'、'批评责备'、'邀请双修'、'其他'

```
【成员互动】掌门对「{成员名}」进行了{互动类型}。

{互动类型 === '夸奖勉励' ? '请根据该成员的性格特点和当前忠诚度/心情，推演夸奖后的效果：成员忠诚度是否提升？心情是否改善？成员对掌门的态度有何变化？' : ''}
{互动类型 === '批评责备' ? '请根据该成员的性格特点和当前忠诚度/心情，推演批评后的效果：成员是否服气？心情是否下降？忠诚度是否受影响？是否有弟子因此产生不满或反而更加勤勉？' : ''}
{互动类型 === '邀请双修' ? '请根据双方境界差距和性格匹配度，推演双修过程：是否顺利？双方修为有无精进？关系是否更加亲密？' : ''}
{互动类型 === '其他' ? '请根据互动内容「{自定义内容}」，推演该互动对成员和宗门的影响。' : ''}

成员信息：
- 姓名：{name}
- 境界：{realm}
- 职务：{role}
- 忠诚度：{loyalty}
- 心情：{mood}
- 性格：{personality.join('、')}
- 外貌：{appearance.join('、')}

请设计一段剧情来交代这个互动，需要交代互动过程、成员的反应、以及互动对成员忠诚度/心情的影响。
```

## 二、宗门组织架构板块

### 2.1 UI 设计

**位置**：宗门页面（sectinfo-page）中，在现有 `sect-info-grid` 下方新增"组织架构"板块。

```
┌─────────────────────────────────┐
│ 宗门志                           │
├─────────────────────────────────┤
│ [现有宗门信息网格]               │
├─────────────────────────────────┤
│ 组织架构                         │
│ ┌─────────────────────────────┐ │
│ │ 0 · 掌门        — 沈万钧     │ │
│ │ 1 · 副掌门      — 暂无       │ │
│ │ 2 · 长老        — 张三、李四  │ │
│ │ 3 · 真传弟子    — 王五       │ │
│ │ 4 · 内门弟子    — 暂无       │ │
│ │ 5 · 外门弟子    — 暂无       │ │
│ │ 6 · 杂役        — 暂无       │ │
│ └─────────────────────────────┘ │
│ [+ 新增职位等级]                 │
├─────────────────────────────────┤
```

**职位行交互**：
- 点击职位名称 → 弹出弟子选择列表，安排/更换该职位的弟子
- 每个职位行右侧有「删除」按钮（掌门不可删除）
- 「+ 新增职位等级」按钮在最下方

**新增职位弹窗**：
```
┌─────────────────────────────────┐
│ 新增职位                         │
├─────────────────────────────────┤
│ 职位名称：<输入框>               │
├─────────────────────────────────┤
│ [确认] [取消]                    │
└─────────────────────────────────┘
```

### 2.2 数据结构

在 `SectSchema` 中新增 `organization` 字段：

```js
organization: zArray(zObject({
  rank: zNumber({ default: 0, min: 0 }),      // 等级序号，0=最高
  name: zString(''),                           // 职位名称
  members: zArray(zString(), [])               // 担任该职位的成员姓名列表
}), [
  { rank: 0, name: '掌门', members: [] },
  { rank: 1, name: '副掌门', members: [] },
  { rank: 2, name: '长老', members: [] },
  { rank: 3, name: '真传弟子', members: [] },
  { rank: 4, name: '内门弟子', members: [] },
  { rank: 5, name: '外门弟子', members: [] },
  { rank: 6, name: '杂役', members: [] }
])
```

### 2.3 交互逻辑

**职位管理**（不消耗体力）：
- 新增职位：`addActionLog('组织架构', '新增职位', `新增职位等级「${name}」`, 0, { type: 'addRole', rank, name })`
- 删除职位：`addActionLog('组织架构', '删除职位', `删除职位「${name}」`, 0, { type: 'removeRole', rank, name })`
- 安排弟子：`addActionLog('组织架构', '人员变动', `安排${memberName}担任${roleName}`, 0, { type: 'assignRole', rank, name, memberName })`
- 移除弟子：`addActionLog('组织架构', '人员变动', `将${memberName}从${roleName}移除`, 0, { type: 'removeMember', rank, name, memberName })`

**职位安排弟子流程**：
```
点击职位行
  → showRoleMemberSelect(roleRank, roleName)
    → 弹窗：显示当前担任该职位的成员 + 可安排的其他成员列表
      → 选择成员 → 确认
        → 更新 organization[rank].members
        → 同时更新 member.role 字段（保持一致）
        → addActionLog（不消耗体力）
```

### 2.4 渲染逻辑

`renderSectInfo` 增强：在现有信息网格后追加组织架构 HTML。

默认从 `sect.organization` 读取，如果缺失则使用默认值。
